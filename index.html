Compatibility is exact and package-specific. An unsupported build is untested, not necessarily broken. Change the scenario to see the permitted path.
Shared engine files, separate game state
Managed Flatpak slots identify app ID, architecture, branch and exact commit. Each managed game receives a separate profile and a hash-bound launch helper. Existing personal profiles are not imported. Different slots may duplicate dependencies.
software/flatpak/<app-id>/<arch>/<branch>/<commit>/
state/<package-id>/<profile-id>/
Preparation can leave a verified engine behind if later game setup fails. Closing the UI does not kill an active Flatpak transaction. No automatic slot cleanup, engine switch or existing-game migration.
